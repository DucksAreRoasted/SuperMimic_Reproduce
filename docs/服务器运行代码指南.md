# 服务器运行代码指南

在一台有 NVIDIA GPU 的 Linux 服务器上准备数据并训练 SuperMimic。默认机器按一张 L40（48 GB）设计：环境数 4096，想象轨迹 4096，显存预算 40 GB。显存更小就用文末的覆盖参数。

机器人：

- 宇树 G1：29 自由度。动作数据的源机器人。
- 宇树 R1：公开 RL 模型是 24 自由度（12 腿 + 2 腰 + 10 臂）。EDU 的 2 自由度头不在这个 MJCF 里。
- Booster K1：22 自由度。

## 1. 上传与安装

把整个仓库放到服务器，包括 `src/`、`scripts/`、`assets/raw/` 和 `pyproject.toml`。`data/` 和 `logs/` 由下面的脚本生成，不必上传。

```bash
cd /path/to/supermimic
python -m venv .venv
source .venv/bin/activate
pip install -U pip
pip install -e ".[data]"
python -c "import torch, mujoco; print(torch.cuda.get_device_name(0), torch.__version__)"
```

需要 Python 3.10 及以上、NVIDIA 驱动，以及能访问 ModelScope（`modelscope.cn`）的网络。数据集不从 Hugging Face 下载。后面的命令都假设已经 `source .venv/bin/activate`。也可以不激活，把 `python` 换成 `.venv/bin/python`：

```bash
PYTHON=.venv/bin/python bash scripts/prepare_data.sh
```

## 2. 一键准备数据

上传仓库之后，在仓库根目录执行这一条即可。脚本会自己建 `.venv`、安装带 ModelScope 下载器的依赖，然后从 ModelScope 拉 LAFAN1，并重定向到 R1 和 K1。

```bash
bash scripts/一键准备数据.sh
```

它内部调用 `scripts/prepare_data.sh`。数据来源是 ModelScope，不是 Hugging Face：

- LAFAN1：`unitreerobotics/LAFAN1_Retargeting_Dataset`，40 条 G1 csv
- BONES-SEED：`bones-studio/seed` 里的 `g1.tar.gz`（约 23 GB）。默认不下载

加上 BONES 的下载和过滤：

```bash
SKIP_BONES=0 bash scripts/一键准备数据.sh
```

连 BONES 重定向到 R1、K1 一起做：

```bash
SKIP_BONES=0 RETARGET_BONES=1 JOBS=16 bash scripts/一键准备数据.sh
```

环境已经装好、只想重跑数据时，可以直接：

```bash
source .venv/bin/activate
bash scripts/prepare_data.sh
```

`scripts/prepare_data.sh` 按顺序做这些事：

1. 下载 LAFAN1 的 40 条 G1 动作。
2. 把它们重定向到 R1 和 K1。
3. 默认不下载 BONES-SEED。`SKIP_BONES=0` 时从 ModelScope 下载并过滤。
4. 只有 `RETARGET_BONES=1` 时，才把过滤后的 BONES 动作重定向到 R1 和 K1。这一步比 LAFAN1 大得多。

只重跑数据、不重建虚拟环境时，用上面的 `prepare_data.sh`。参数和一键脚本相同。

可调环境变量：

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `JOBS` | 8 | 重定向的并行进程数 |
| `RETARGET_LAFAN` | 1 | 设为 0 则只下载，不重定向 LAFAN1 |
| `SKIP_BONES` | 1 | 设为 0 才下载并过滤 BONES-SEED |
| `RETARGET_BONES` | 0 | 设为 1 才重定向过滤后的 BONES |
| `PYTHON` | `python` | 指定解释器 |
| `MODELSCOPE_TOKEN` | 空 | 可选，提高 ModelScope 限速 |

脚本可重复执行。重定向时已经存在的 npz 会跳过。

## 3. 分步命令

总入口只是把下面三支脚本串起来。需要重跑某一步时直接调用。

### 3.1 下载

下载走 ModelScope，使用轻量的 `modelscope-hub`，支持断点续传。

```bash
python scripts/download_datasets.py --dataset lafan1
python scripts/download_datasets.py --dataset bones
python scripts/download_datasets.py --dataset all --dest data
```

结果：

- `data/lafan1/g1/*.csv`：40 个文件，30 Hz，列是根位置、xyzw 四元数、29 个关节。ModelScope 仓库 `unitreerobotics/LAFAN1_Retargeting_Dataset`。
- `data/bones/g1.tar.gz`：约 23 GB。ModelScope 仓库 `bones-studio/seed`。
- `data/bones/metadata/seed_metadata_v004.csv`：元数据。

两个仓库在 ModelScope 上都是公开的，不需要 Hugging Face 令牌。限速时可设置 `MODELSCOPE_TOKEN`。仓库 id 可以用 `--lafan-repo` 和 `--bones-repo` 改。

### 3.2 过滤 BONES-SEED

论文附录 E 的两步：先按文件名去掉地形和物体交互，再做几何可行性检查。翻转、侧滚不会被名字规则删掉。

只看一份文件名列表：

```bash
python scripts/filter_bones.py --names clips.txt --out data/bones/kept.txt
```

从压缩包解出保留下来的动作，并做可行性检查：

```bash
python scripts/filter_bones.py \
  --archive data/bones/g1.tar.gz \
  --out data/bones/kept.txt \
  --rejected-out data/bones/rejected.tsv \
  --extract data/bones/g1_filtered \
  --feasibility
```

`kept.txt` 是留下的文件名。`rejected.tsv` 是删掉的文件名和原因。解压结果在 `data/bones/g1_filtered/`。可行性检查按 G1、50 Hz 的阈值，会逐帧做运动学，时间很长。

论文过滤后大约是 129,514 条。名字规则是按公开的 SONIC 词表改过的，条数可能有少量出入，以 `kept.txt` 的行数为准。

### 3.3 重定向到 R1 和 K1

G1 动作按站立高度缩放关键点，再用阻尼最小二乘逆运动学写到目标骨架。输出是 50 Hz 的 npz：`qpos`（四元数 wxyz）、`qvel`、`name`。

单条：

```bash
python scripts/retarget.py \
  --csv data/lafan1/g1/walk1_subject1.csv \
  --target r1 \
  --out data/retarget/lafan1/r1/walk1_subject1.npz
```

整个目录，两个机器人一起：

```bash
python scripts/retarget.py \
  --input data/lafan1/g1 \
  --targets r1,k1 \
  --out data/retarget/lafan1 \
  --jobs 8
```

BONES 过滤结果同样处理：

```bash
python scripts/retarget.py \
  --input data/bones/g1_filtered \
  --targets r1,k1 \
  --out data/retarget/bones \
  --jobs 16
```

常用参数：

- `--src-fps 30`：csv 的原始帧率，脚本会重采样到 50 Hz。npz 视为已经是 50 Hz。
- `--iterations 8`：每帧逆运动学迭代次数。
- `--limit 2`：只处理前 2 条，用来确认流程。
- `--force`：覆盖已经写好的 npz。

目录结构：

```text
data/retarget/lafan1/r1/*.npz
data/retarget/lafan1/k1/*.npz
data/retarget/bones/r1/*.npz
data/retarget/bones/k1/*.npz
```

## 4. 训练

默认就是论文的单卡配置（4096 环境、想象视野 32、每次 4096 条想象轨迹）。一张 L40 上按这个跑。想象反传会按剩余显存切块，梯度累加后与一次完整更新相同。

G1，LAFAN1 的 40 条：

```bash
python scripts/train.py \
  --robot g1 \
  --motions data/lafan1/g1 \
  --device cuda \
  --log-dir logs/g1_lafan1
```

R1 或 K1，用重定向结果。目录里只有 npz 时会走 npz 读取；如果同一目录里还有 csv，会优先读 csv。

```bash
python scripts/train.py \
  --robot r1 \
  --motions data/retarget/lafan1/r1 \
  --device cuda \
  --log-dir logs/r1_lafan1

python scripts/train.py \
  --robot k1 \
  --motions data/retarget/lafan1/k1 \
  --device cuda \
  --log-dir logs/k1_lafan1
```

G1 全量 BONES：

```bash
python scripts/train.py \
  --robot g1 \
  --motions data/bones/g1_filtered \
  --device cuda \
  --log-dir logs/g1_bones
```

结束时写出 `logs/<name>/policy.pt` 和 `policy.onnx`。加 `--eval` 会在训练后再把每条动作评一遍，40 条以上会很久。速度接口是 `--velocity`。

显存不到 48 GB 时不要用默认的 4096。例如 24 GB 卡可以先用：

```bash
python scripts/train.py \
  --robot g1 \
  --motions data/lafan1/g1 \
  --num-envs 1024 \
  --imag-batch 1024 \
  --wm-batch 1024 \
  --device cuda \
  --log-dir logs/g1_lafan1
```

这会改变论文的 batch，只适合先把流程跑通。要对照论文的 0.82 归一化回报，用默认 batch，在 L40 上训练。

评测一个已有权重：

```bash
python scripts/eval_benchmark.py \
  --robot g1 \
  --motions data/lafan1/g1 \
  --checkpoint logs/g1_lafan1/policy.pt \
  --device cuda
```

`--hidden` 必须和训练时一致。默认 2048 是论文宽度。训练时如果传了 `--hidden 256`，评测也要传 `--hidden 256`。

## 5. 磁盘

| 内容 | 大约占用 |
| --- | --- |
| LAFAN1 的 40 条 csv | 几十 MB |
| LAFAN1 重定向到 R1 和 K1 | 与 csv 同一量级 |
| BONES `g1.tar.gz` | 23 GB |
| 解压并过滤后的 G1 动作 | 再留出数十 GB |
| BONES 重定向到两台机器人 | 与过滤后的库同一量级，另算 |

建议空闲空间至少 80 GB 再开 BONES。LAFAN1 单独跑不受这个限制。

## 6. 建议的服务器顺序

1. `bash scripts/一键准备数据.sh`。它会建虚拟环境、安装依赖，并从 ModelScope 下载 LAFAN1，再重定向到 R1 和 K1。
2. 确认 `python -c "import torch; print(torch.cuda.get_device_name(0))"` 能看到 GPU。
3. 在 L40 上用默认参数训练 G1 的 LAFAN1。
4. 需要论文的大数据集时再 `SKIP_BONES=0 bash scripts/一键准备数据.sh`，最后按需加上 `RETARGET_BONES=1`。
